# answer engines are welcome on everything except the admin console and the private API.
#
# Machine-readable summaries, in increasing order of detail:
#   https://www.digidental.us/llms.txt        — index, llmstxt.org format
#   https://www.digidental.us/llms-full.txt   — full plain-text brief (pricing, FAQ, terms)
#   https://www.digidental.us/api/site-info   — JSON, same facts, with sources
#
# ---------------------------------------------------------------------------
# HOW THIS FILE IS STRUCTURED — read before editing
# ---------------------------------------------------------------------------
# A robots.txt group does NOT inherit from the "User-agent: *" group. The moment a
# crawler finds a group naming it, that group becomes the ONLY one it obeys and the
# wildcard group is ignored entirely (RFC 9309 §2.2.1).
#
# This file previously listed every named bot with a bare "Allow: /" and kept the
# admin/API disallows only in the "*" group. The effect was the exact opposite of what
# it looked like: Googlebot, GPTBot, ClaudeBot, PerplexityBot and every other named
# agent were told the admin console and the whole API were fair game, while only
# unnamed crawlers were restricted.
#
# So: every group below repeats the SAME rule set in full. Multiple User-agent lines
# stacked before one rule block form a single group that applies to all of them, which
# is how the repetition stays manageable. If you add a rule, add it to all three groups.
#
# The /api/ disallow is deliberately punched through for three endpoints:
#   /api/site-info — the JSON summary we want answer engines to read
#   /api/video     — the <video> sources, and the <video:content_loc> in sitemap.xml.
#                    Blocking it means Google cannot verify either clip and drops both
#                    VideoObjects from rich results without reporting an error.
#   /api/image     — the founder portrait and dashboard captures referenced by the
#                    Person and ImageObject nodes in the homepage JSON-LD.
# Allow wins over Disallow here under both matching rules in use in the wild: it is the
# longer (more specific) path for RFC 9309 parsers, and it appears first for the older
# first-match-wins parsers.
